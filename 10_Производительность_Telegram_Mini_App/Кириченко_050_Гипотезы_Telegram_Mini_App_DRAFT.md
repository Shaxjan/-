## 1. Разделить общие и условно React-специфичные причины

**Общие для любого JS Mini App:** обработчики, async/await и network, ненужные timers, DOM/layout/paint, память и декодирование ресурсов, слишком частые обновления, зависание на bootstrap и Telegram WebView.

**Только если реально есть React:** render/commit commits, component mount/unmount, effect cleanup, hydration, context provider fan-out, props changes, state store dispatch, роутинг компонентов, reconciliation. Не утверждать этот стек в «Мире Поттера» без фактов.

## 3. Приоритет исследования для жалобы «после подключения переключение вкладок и зельеварение сильно лагают»

1. Сначала **не делать вывод о React**. Узнать стек в отдельном read-only аудите по разрешению владельца. До этого замерять пользовательское действие вне зависимости от framework: tap → callback → data/resource wait → paint → отзывчивость.
2. Затем **K50-01, K50-05, K50-06, K50-09**: общие и правдоподобные механизмы. Порядок можно менять по фактам трассы; это **не диагноз**.
3. При наличии React и явном признаке повторных обновлений — **K50-02–04, 07–08, 12**.
4. Держать **K50-11** в стороне, пока трасса не покажет участие аудио/изображений.
5. После утверждённого **отдельного ТЗ** протестировать один адресный фикс на изолированном стенде и сравнить старый и новый билды **на том же телефоне**, контролируя WebView, кэш, сеть, стабильность, память и регрессии.

## 4. Минимальный обезличенный протокол

- Время события, версия фронтенда, версия Telegram/Android System WebView, тип сети, холодный/тёплый старт, режим (вкладка/зельеварение/вопросы), физическое устройство без уникального идентификатора.
- Длительность пользовательского действия, задержка первого видимого кадра, длинные JS tasks, рендер кадров, начало/конец отдельных сетевых запросов, heap trend, ошибки без полезной нагрузки пользовательских данных.
- **Запрещено** собирать `initData`, токены, auth cookies, тексты переписок и имена пользователей в «диагностике производительности».
- Не заявлять p99 по маленькой выборке. Показывать каждое время и разброс при N маленьком.
- Показатели задержки **до исследования неизвестны**, не придумывать «реальные FPS» или «улучшилось на X%».

## 5. Книжные ограничения

React/TS пособие 2023 года — базовое объяснение механизмов, **не учебник по profiling** и не инструкция для mobile Telegram WebView. Create React App официально deprecated в 2025 году (https://react.dev/blog/2025/02/14/sunsetting-create-react-app); `reportWebVitals()` сам по себе не отправляет данные в Google Analytics (https://create-react-app.dev/docs/measuring-performance/). Не копировать примеры React Router старого API, учебную форму с одним `isValid`, старые синтаксисы TS и псевдоэффективные паттерны.
