# Производительность Telegram Mini App — исследовательское направление

**Назначение:** исследования книг для построения доказуемой методики диагностики задержек Telegram Mini App («Мир Поттера»). **НЕ** является разрешением менять код игры, её GitHub-репозиторий, инфраструктуру или production.

## Принципы работы

1. **Первичный книжный источник — Яндекс Книги.** Читать доступное русское издание **по полным разделам**, с самостоятельной сверкой схем, таблиц и сносок. Если авторизованная читалка пишет «книга недоступна», фиксировать **BLOCKED**, не подменять полный текст внешним конспектом. Доступный публичный фрагмент можно изучать, но нельзя засчитывать непоказанные главы.
2. **Сначала измерение, потом изменение.** Каждый предполагаемый источник лагов описывается как гипотеза, с наблюдаемым симптомом, инструментом измерения, критерием подтверждения/опровержения и возможной издержкой измерения.
3. **Разделять пользовательскую задержку на ветви:** интерфейс/главный поток JS; layout/paint/composite и WebView; изображения/аудио и память; загрузка ресурсов и транспорт/TLS; API/backend/очереди; база данных/диски; особенности Telegram WebView/жизненного цикла Android.
4. **Не путать корреляцию с причиной:** наличие музыки/анимации, тяжёлого изображения или медленного API не доказывает его роль в конкретном лаге без временной привязки к торможению.
5. **Сравнивать одинаковые сценарии**, фиксировать устройство, Android/WebView/Telegram и версии клиента/сервера, режим сети, нагрузки, температуру/энергосбережение, данные предыдущего запуска и кеширование; отдельно холодный и тёплый вход.
6. **Без вмешательства в игру.** Никаких изменений `Shaxjan/potter-quiz`, CI, деплоя, БД, токенов, живых пользователей и production. Готовить только проверяемые, отдельно обозначенные **DRAFT / NOT TESTED** методики для будущего решения владельца.
7. **Публикация учебного исследования:** карточка источника → контроль доступа → последовательный текстовый разбор → протокол графики и примечаний → ограничения применимости → отдельные гипотезы → финальная приёмка. **Draft PR не сливать**.

## Исследовательские вопросы, характерные для Telegram Mini App

| Вопрос | Что требуется отличить | Вариант будущего измерения; НЕ выполнено |
|---|---|---|
| После загрузки вкладки подвисает ввод | главная нить JS, React/Vue/обычный DOM, GC, декодирование изображений, синхронный layout | Performance trace и Long Tasks на реальном Android WebView |
| Зельеварение «замирает» | логика, частые timers, canvas/CSS, аудиодекодирование, сеть | marker «действие → первый ответ → первый плавный кадр», связка с Timeline |
| Переключение табов каждый раз медленнее | утечки подписок/слушателей, разрастание DOM, неосвобождённые медиа | последовательность из N одинаковых переключений, память и число слушателей до/после |
| Первое открытие или повторный вход зависает | TLS/JS/CSS delivery, bootstrap/auth/API, кеши и Service Worker | отдельная сеть и загрузка ресурсов, request waterfall с тайм-аутами |
| Плавная прокрутка, но ожидание ответа | backend/API/SQLite/WAL/очереди | correlation ID и server timing; read-only журналы с разрешением, без персональных данных |
| Только внутри Telegram, но не в обычном Chrome | webview версия, Telegram bridge, lifecycle, ограничения аппаратуры | A/B одного билда на одном Android, внутри Telegram vs Chrome, одинаковые сети и шаги |

## Книги — рабочая очередь

- **№047 — Ричард Л. Сайтс, «Software Dynamics: оптимизация производительности программного обеспечения».** [Исследовательский файл](./Сайтс_Software_Dynamics_047_DRAFT.md). [Полное русское издание в каталоге Яндекс Книг](https://books.yandex.ru/books/X1Ev4cFw), [публичный фрагмент](https://books.yandex.ru/books/X1Ev4cFw/read-online). **Статус: ВВЕДЕНИЕ И ПРЕДИСЛОВИЕ ИЗ ФРАГМЕНТА ПРОЧИТАНЫ; ПОЛНАЯ ЧИТАЛКА BLOCKED («книга сейчас недоступна»); главы 1–30 — НЕ ПРОЧИТАНЫ; DRAFT.**
- **№2 по приоритету — Джереми Вагнер, Web Performance in Action.** Особенно JS, браузерный рендеринг, изображения, кеш, сеть. Наличие полного текста в Яндекс Книгах не подтверждено, английское издание не приравнивать к утверждённому русскому книжному источнику.
- **№3 — Эдди Османи, Learning JavaScript Design Patterns (2-е издание).** Архитектура/связность/динамический импорт; доступность в Яндекс Книгах пока неизвестна.
- **№4 — Брендан Грегг, «Производительность систем».** Приоритет только если признаки сервера/ОС и задержек по CPU/диску/памяти.
- **№5 — Андрей Акиньшин, «Профессиональный бенчмарк».** Стабильность сравнений, критерии шума/воспроизводимости.

Остальные предложенные книги сохраняются в списке кандидатов, не объявляются изученными. Очередь корректируется только по фактическому доступу и диагностической полезности.
