## E. Критерии допуска к использованию в проекте

Не передавать в программирование прямые листинги без технической актуализации. Допустить **только** схему будущей диагностики: определить, используется ли React; если используется — на каком уровне роутинг/стейт/эффекты; сравнить lifecycle и количество повторных операций, затем по трейсингу определить критический путь лагов. Если React нет — использовать лишь общие идеи управления ресурсами, API и событий, **не переписывать игру на React**.

Никаких действий с `Shaxjan/potter-quiz`, Telegram production, базой данных, CI. Замеров задержек игры **0**, утверждённых продуктовых гипотез **0**.
