# ТЗ №93 — браузерный рендеринг и плавность «Мира Поттера»

Дата: 24.10.2026. Это дополнение к каталогу №92, а не утверждение о плавности production.

## Отбор и предел чтения

Основной поиск выполнен в авторизованном каталоге Яндекс Книг по JavaScript, HTML/CSS, веб-производительности, графике, SVG, Canvas, WebGL, браузерным движкам и алгоритмам. Современного доступного в браузере технического учебника о Chrome/Android WebView, Raster и Compositing каталог не дал. Найденное методическое пособие Ботова прочитано по доступным разделам; оно полезно для сравнения моделей Canvas/SVG, но не отвечает на вопрос о GPU и реальном Android. Профессиональная книга «Оптимизирующие компиляторы» была доступна только в приложении; её текст через браузер не изучался и в библиотеку знаний не засчитывается. Лимиты доступа не обходились.

Чтобы закрыть именно технический пробел, изучены относящиеся к задаче главы открытой авторской книги [Web Browser Engineering](https://browser.engineering/index.html) и сверены с [официальным руководством Chrome DevTools Performance](https://developer.chrome.com/docs/devtools/performance/reference). Не прочитанные главы книги не объявляются завершёнными.

| Материал | Фактический объём | Итог |
|---|---|---|
| [М. Ботов, «Интерактивная анимация HTML5»](https://books.yandex.ru/books/QyqqlTcX), Яндекс Книги, 2017 | Предисловие, главы 1–2, основные подразделы главы 3 и глава 4. Конец большого листинга упражнений главы 3 обрезан интерфейсом доступности; вся книга **не** отмечена как прочитанная без пробелов. | Canvas убирает объекты рисунка из DOM; SVG оставляет адресуемые узлы. Старые примеры `setInterval`/jQuery/SMIL не подтверждают современной мобильной производительности. |
| [P. Panchekha, C. Harrelson, *Web Browser Engineering*](https://browser.engineering/index.html), 2025 | Адресно изучены главы 11–13 и 16: визуальные эффекты, планирование и кадры, анимация/композитинг, инкрементальное обновление. Остальные главы **не** проходились последовательно. | Рендер — цепь задач и переиспользуемых слоёв; стоимость нового кадра не сводится к длительности JS и объёму сети. |
| [Chrome DevTools: Performance features reference](https://developer.chrome.com/docs/devtools/performance/reference) | Разделы runtime trace, screenshots, GPU и raster activity. | Для решения о Potions нужны реальный представленный кадр, Raster/GPU и Paint, а не один `requestAnimationFrame` gap. |

Выводы для игры и измерения — в [проектном синтезе](../09_Применение_к_проектам/TZ93_Рендеринг_и_плавность_Мира_Поттера.md). Исходные книги не копировались в репозиторий.
